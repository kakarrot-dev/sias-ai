# PRD：智能体中心原型重构

> 当前范围（2026-09-15）：数字助理、普通专家、队长与专家团暂不在后台调试。后台保留配置、授权、发布及记录；发布不依赖后台测试报告。旧版页面入口同样适用。第 8 节此前验收保留为历史证据。

> 2026-09-16 输入输出调整：[配置与填写设计](audits/2026-09-16-agent-input-output-design.md)。此设计替代早期把输入输出折叠于运行配置的方案，历史验收结果保留。

> 2026-09-16 用户纠正：专家团只负责组队，业务输入输出在成员智能体设置。此前团队独立表单与交付约定的方案已撤回，以[专家团组队边界修正](audits/2026-09-16-team-assembly-boundary.md)为准。

## 1. 摘要

面向实施人员、平台开发者与学校信息化处管理员，重构现有后台智能体中心的页面和交互。交付是可操作、可保存、可验证的浏览器原型；详细规则保留在需求文档，页面只展示完成当前操作需要的信息。

本文件是本次原型的交付范围与验收映射。产品决策来源：[智能体中心 PRD](../../obsidian-wiki/project/数字员工/详细设计/PRD-智能体中心.md)及本次对话确认；原有 `web-admin-spec.md` 中冲突的 11 步配置、队长提示词编排、独立发布、发布前必须授权等描述由本文替代。

## 2. 参与者

| 角色 | 工作 | 原型身份 |
|---|---|---|
| 平台开发者、实施人员 | 配置模型、维护标准 Skill 与工具，联调业务能力 | 业务配置人员 / 平台管理员 |
| 学校信息化处管理员 | 选择已发布资源、授权、启停、检查影响 | 平台管理员 |
| 发布授权人 | 核对配置与变更影响，发布版本 | 发布授权人 |
| 审计人员 | 查看配置、版本与操作记录 | 审计人员 |

同一人可以同时拥有配置、发布权限。V1 不要求双人审批；保留旧申请记录用于追溯。

## 3. 背景

原型把身份提示词、SOP、资源授权、输入输出、运行限制拆成 11 步，并在首屏混入使用授权。部分交互仍把普通专家当队长、让队长独立发布，与已确认模型不一致。

本次合并任务步骤、保留已有字段与本地保存能力，不扩展到其他后台模块或真实执行引擎。旧发布快照与历史证据不随表单转换改写；旧配置若不符合新规则，展示具体待完善原因。

## 4. 目标与完成标准

- 本次交付中，普通专家创建为 4 步，队长与专家团创建为 3 步；未完善配置允许存草稿。
- 页面区分数字助理、普通专家、队长与专家团，避免角色混用。
- 下面每项用户故事都有可操作入口、预期结果和验证记录。
- 保存、刷新、版本冻结、工具确认、授权独立、队长专属关系均完成回归测试。
- 交付前完成后台类型检查、测试、构建和实际浏览器主流程检查。通过模拟不等于真实模型或业务联调通过。

## 5. 用户工作与范围

实施人员需要把开发好的工具和 Skill 组成可交付能力；学校管理员需要知道谁能使用、何时可发布、停用会影响谁。

V1 使用现有本地目录与存储，不增加独立评测平台、长期记忆、动态成员、嵌套专家团或真实工具调用。模拟身份与目录仅用于原型，不得当作真实高校权限。

## 6. 价值

用任务顺序引导配置，把通用执行规则放在文档中，把关键差异落实成控件限制、校验与影响提示。配置人员能够先保存不完整草稿；管理员能够分开管理发布版本和使用范围。

## 7. 方案、用户故事与验收

### 7.1 页面结构

- `/agents`：数字助理 / 智能体 / 专家团三个入口。智能体列表同时包含普通专家和队长，展示角色与使用方式。
- 智能体中心列表通过“创建”按钮弹窗选择普通专家、队长智能体或专家团，选择后直接进入对应创建页；取消保留当前筛选与列表。旧 `/agents/new` 类型选择页面保留兼容。
- 普通专家创建：基本信息 → 工作能力 → 输入与输出 → 检查配置。开场白与推荐问题在基本信息中选填；工作能力中可选择模型。
- 队长创建：基本信息 → 协作能力 → 检查配置。只配置身份职责、协调模型与人工兜底；协作页优先说明分派、收集结果、汇总交付三项职责，内置规范只读查看，不展示禁用的业务工具权限表单。无独立用户表单，编辑页提供所属团队的配置入口。
- 已保存对象：增加“运行配置”入口与分区，按需调整上下文、运行限制及对话偏好；普通专家拥有独立的输入输出配置入口，专家团只维护组队关系；继续提供发布管理、使用授权、版本与记录。队长进入所属专家团发布，不开放独立聊天与授权。
- 专家团：基本信息 → 队长与成员 → 检查团队。配置团队名称、简介、归属、专属队长和固定版本成员；业务表单、资料限制、成果、模板、校验与完成条件由各普通专家维护。队长草稿与团队一起发布。

### 7.2 用户故事（Card / Conversation / Confirmation）

#### US-01：容易开始配置

作为实施人员，我希望先定义身份再补充能力，以便尽快保存第一版。设计：`#/agents/new/expert`。

1. 创建显示四步，可直接切换；“输入与输出”独立展示，配置用户表单、成果与完成条件。运行参数继续使用默认值。
2. 名称与归属有效即可保存草稿；标识自动生成且保存后固定。
3. 身份与职责统一在系统提示词中维护。新建普通专家与队长使用相同的空白结构，仅保留“身份、服务对象、职责范围、职责边界、表达要求”五个标题，不预填角色或业务正文；不再单列“补充职责边界”四个字段。业务步骤由 Skill 提供。
4. 刷新保留有效暂存；取消离开不丢输入；保存失败保留填写内容。
5. 查看发布配置只读；创建新草稿不修改历史版本。
6. 旧暂存中的自定义运行参数与契约继续保留；无效参数保存时定位到修正入口，不静默覆盖。

#### US-02：明确工作方法与具体工具权限

作为实施人员，我希望选择固定版本 Skill 并逐项配置工具，以便准确控制能力。设计：`#/agents/{id}/edit/skills`。

1. Skill 原文只读，可查看；无人工固定执行顺序或优先级。
2. 新选择 Skill 不自动启用其依赖工具；必需工具未启用时阻止发布。
3. 普通专家可配置业务工具；每个工具单独选择身份、范围和确认人。
4. 写操作要求前置确认；无幂等保障时不自动重试。
5. 修改版本、输入输出或工具后，原测试报告转为历史记录并保留，不参与发布判断。

#### US-03：明确运行与交互

作为实施人员，我希望配置用户怎样补充信息、确认操作和应对失败，以便前台能按业务需要呈现对话或表单。设计：`#/agents/{id}/edit/input`；后台不提供任务调试。

1. 创建采用默认运行配置；可在工作能力中按需展开用户交互，配置输入字段、必填条件、文件限制与缺失输入处理方式，保存后继续维护。
2. 可配置输出格式、字段、来源和交付确认；页面实时展示效果。
3. 可配置上下文来源、历史策略与预算；保留任务关键状态约定。
4. 用户补充信息、操作前确认、业务审批、异常接管分别定义；异常接管按需启用，审批权限继续由业务系统认定。
5. 执行次数、时长、Token、无进展限制与结果未知处理可配置；取消停止后续步骤，已产生的结果和证据保留。

#### US-04：组建专属专家团

作为实施人员，我希望直接找到可用队长并选择普通专家，以便组成职责清晰的团队。设计：`#/agents/new/team`。

1. 明确区分队长和普通专家；角色创建后固定。
2. 一队长最多一专家团；已在其他团队或历史发布中绑定的队长不可选。
3. 发布时有一名队长和至少两名不同普通专家；无重复、嵌套或动态成员。
4. 普通成员固定已发布版本；不跟随新版本。队长已保存草稿可与团队共同发布，草稿变化需重新选用。
5. 队长只用平台内置分派、获取结果和汇总能力；成员业务工具仍按自身权限执行。团队用户无需额外取得成员独立使用许可。
6. 专家团只负责组队，输入字段、用户表单、附件、输出格式与完成条件属于各普通专家。队长依据任务分派成员并汇总结果，不在团队创建第二份配置。修改成员草稿不改变团队的固定版本引用。
7. 团队发布校验基本资料、队长专属关系、成员数量、角色、固定版本及依赖可用性；业务表单、附件、回执等在普通专家自己的发布流程校验。历史团队表单保留为兼容数据，不再展示、继承或参与团队校验，历史快照不改写。
8. 创建采用三步导航与固定底部操作，允许直接切换步骤；名称为空时保存返回基本信息并聚焦名称。成员未齐时展示中性指引，在检查页集中显示待办，既有失效引用仍及时提示。
9. 普通专家通过独立弹窗多选；搜索保留勾选，确认后统一添加固定发布版本，取消不改草稿。检查页按基本信息、队长与成员分组，可直接定位修改；摘要使用实际引用版本。

#### US-05：分开管理发布与可用范围

作为学校管理员，我希望先发布稳定版本，再决定向谁开放。设计：`#/agents/{id}/edit/release`、`edit/grants`。

1. 发布前自动核对当前保存配置的必填项、模型与能力引用、工具权限、授权同步和团队组成，不要求调试或测试报告。
2. 有发布权限者可直接发布，无强制申请流程；尚无使用授权也可发布。
3. 普通专家可设为仅团内使用或允许独立使用；调整立即作用于后续请求和旧会话新请求。
4. 明确禁止优先于允许；发布、回退不恢复已经撤销的授权。
5. 数字助理仅匹配当前用户有权使用且可用的公开普通专家与专家团；排除队长、内部专家和不可用对象。

#### US-06：看清变更影响并保留证据

作为学校管理员，我希望停用前看到受影响对象，以便有依据地管理。设计：`#/agents/{id}/edit/history`。

1. 停用确认展示受影响团队与进行中任务，阻止新的依赖调用。
2. 已发出的业务动作不能被“停用”假装撤销，保留回执；原型仅模拟状态。
3. 发布新版本不会恢复停用；独立“恢复可用”检查依赖后生效，旧任务仍需发起人确认。
4. 未发布、无团队引用、无业务运行的草稿可清理，即使有已完成测试；配置、报告和审计记录保留。
5. 存储失败回滚本次变更，版本冲突保留输入，读取失败不重复创建对象。

#### US-07：管理全校统一数字助理

作为学校平台管理员，我希望集中查看和修改数字助理配置，以便维护统一入口，不把它当成可批量创建的业务专家。设计：`#/agents?kind=assistant`。

1. 数字助理页展示一个预置对象及当前发布版本、草稿状态、运行模型、责任人与更新时间；不展示新增、删除、搜索或分页控件。
2. 新增由学校初始化完成；后台不允许重复创建、复制、删除或停用唯一数字助理。缺少对象时说明尚未初始化，不引导创建普通专家。
3. 查看配置保持只读；常规设置合为一页。旧版提示词、输入、输出、工作方法、匹配链接进入精简设置，额外配置通过独立维护入口查看。
4. 平台管理员可进入草稿编辑；已发布版本先创建草稿。保存及刷新保留修改，当前发布快照不变；未保存离开保护复用现有机制。
5. 继续复用发布、历史快照和回退功能。已有测试报告只读保留；回退只影响后续使用，不撤销历史业务结果。
6. 审计人员仅查看；部门配置人员无权管理数字助理。对象数量和操作权限同时由本地状态动作校验，不只通过隐藏按钮限制。

| 操作 | 数字助理管理方式 |
|---|---|
| 增 | 学校初始化预置，保证全校唯一 |
| 删 | 保留统一入口，禁止删除与复制 |
| 改 | 编辑草稿 → 核对配置 → 发布新版本 |
| 查 | 只读查看配置、当前运行版本、历史版本及记录 |

#### US-08：只配置数字助理需要的内容

作为学校管理员，我希望在一页内调整数字助理身份和接待用语，以便不用理解业务专家的输入输出契约和执行参数。设计：`#/agents/assistant/edit/basic`。

1. 详情导航只有基础设置、让修改生效、谁能使用；“修改记录”为页头次要入口。基础设置包含下表 7 项，不再拆分 6 个配置页签。
2. 身份提示词只描述身份、职责与通用表达，不承担 SOP；内置接待规则可只读查看标准 Skill 原文，不在常规页面添加业务工具或重复配置匹配权限。
3. 日常问答和匹配共用一个模型字段；更换时保持现有模型引用一致。开场白选填，无匹配反馈必填。
4. 更改上述内容不清除已有输入输出约定、排除对象、Skill 固定版本或运行参数；检测到额外配置时才展示“维护已有配置”，维护后可返回精简设置。已有参数无效仍阻止发布，并保留维护路径。
5. 已发布配置和历史版本以只读精简视图展示；保存只改变草稿。旧链接兼容、刷新持久化和管理员/审计权限继续有效。

| 常规字段 | 用途 |
|---|---|
| 名称 | 统一入口名称 |
| 简介 | 告诉师生可以获得哪些帮助 |
| 责任人 | 维护与问题归属 |
| 使用的 AI 模型 | 日常问答与意图匹配共用模型 |
| 身份提示词 | 身份、职责及通用表达要求 |
| 开场白 | 用户开始对话时的提示，允许留空 |
| 无匹配反馈 | 找不到可用承接对象时的引导 |

权限筛选、内部专家与队长排除、单候选转交、多候选选择、无匹配返回由内置接待规则约束；权限仍以使用授权与目标对象的有效状态为准。输入输出业务契约、写前确认及完成验收由真正承接业务的专家或专家团负责。已有数字助理的定制配置不在本次 UI 调整中迁移或重置，保留兼容维护和原始快照。原型匹配仍为固定算法示意，Skill 正文展示不等于接入真实执行引擎。

#### US-09：用具体操作完成助理维护

作为学校信息化处管理员，我希望直接调整设置、确认生效、管理使用范围及恢复旧版，以便维护统一接待入口。

| 入口 | 用户任务 | 页面内容与完成结果 |
|---|---|---|
| 基础设置 | 调整身份和接待用语 | 7 项设置；保存后提示到“让修改生效”确认 |
| 让修改生效 | 核对并启用保存的设置 | 自动检查配置完整性；问题可定位修正；填写“这次改了什么”并确认生效 |
| 谁能使用 | 向部门或人员开放 | 选择可使用部门/人员，可单独排除；预览指定人员能否使用；保存独立生效 |
| 修改记录 | 找回以前的设置 | 按版次从新到旧显示日期、修改人、说明和“正在使用”；查看或重新使用旧版 |

1. 保存不自动生效；发布保留配置完整性、权限与引用检查。无测试报告、旧测试失败或报告过期均不阻止发布。
2. 发布和重新使用旧版只影响后续使用，保留当前授权、已有业务运行和待生效修改。
3. 当前操作只写入浏览器本地原型数据，不代表真实模型质量或业务联调通过。
4. 审计人员只读，部门配置人员仍不能管理统一助理。已有输入输出、Skill 版本、排除对象和运行参数原样保留，额外配置仍可维护。

#### US-10：后台暂不提供智能体调试

作为实施人员和学校管理员，我希望后台只承担配置与管理任务，以便不必在创建、编辑或发布时执行调试。

1. 范围覆盖数字助理、普通专家、队长、专家团及保留的旧通用 Agent/专家组页面。
2. 创建、详情、列表及兼容维护路径均不提供调试、试用、预览交互、样例预演、固定样例运行或测试集选择入口。
3. 发布条件继续使用同一套字段、模型/工具引用、权限、团队人数与固定版本校验。移除测试报告前置后，队长仍只能随所属专家团发布。
4. 旧版专家组快速搭建在核对配置后直接保存草稿，不再进入预演步骤；旧 `sample` 地址进入配置页。
5. 既有测试数据、历史配置和业务记录不清除。历史测试报告可从记录中只读查看，不提供重新运行，也不作为当前发布条件。
6. 输入输出、人工介入、失败处理和工具写前确认仍可配置；本轮撤下的是后台执行与对话演示。调试的后续入口另行规划，本轮不新增其他端的调试页面。

#### US-11：职责只维护一份

作为配置人员，我希望直接在系统提示词中说明身份与职责，以便避免多份说明互相冲突。

1. 新建时提示词保留五个空标题。正文可自由修改，不要求每节必填，也不通过模板增加业务规则。仅有标题可保存草稿，发布时提示补充具体内容。
2. 空白模板直接预填在新建智能体的系统提示词输入框中，不提供模板按钮。用户可直接填写、修改或清空，已有提示词不自动覆盖或追加模板。保留全屏编辑与信息变量入口，正文上限为 4000 字。
3. 既有提示词不自动替换。原职责字段有内容时提供只读查看与一次性合并：完整追加旧文本后清空原字段，保存草稿后才生效；取消/离开保护沿用现有机制。超出字数上限时阻止合并，完整保留原值与提示词；历史版本保持原样可查。
4. 原字段仅为旧版兼容记录，不再开放独立编辑。新版本职责以系统提示词为准，Skill 负责工作方法与 SOP；任务必需输入在输入契约中配置。服务对象说明不授予访问权限，禁止任务描述不替代实际工具权限和平台限制。

#### US-12：按需配置人工兜底

作为实施人员，我希望只给需要人工承接的智能体配置兜底人员，使文稿生成、普通问答等任务无需绑定业务处理人。

1. 新建默认关闭“出现问题时转人工”，不默认使用智能体责任人；开启后才展示接管人员。允许暂未选择人员的草稿，发布时必须选择有效人员。当前原型支持人员目录；按岗位动态分派需接入学校岗位与值班目录，不虚构岗位数据。
2. 开启后，无法自动恢复的执行失败、超时或无进展进入等待接管；写操作结果未知先核验原动作，无法确认再接管，禁止重新发送。缺失输入与知识不足仍使用各自已配置的处理方式，可显式选择转人工。
3. 关闭后，无接管人员也是合法配置。不能继续时停止并保留已完成内容、未完成事项及原因；未知业务动作保留“结果待核验”，不能报成功或允许盲目重试。
4. 从开启改为关闭时保留原接管人供恢复；依赖人工的缺失输入处理改为停止并提示缺项，证据不足改为说明缺口，未知结果处理改为核验后停止。页面说明关闭的影响，业务操作前确认节点与业务审批权限保持独立。
5. 原配置没有开关字段但有接管人员时，按已开启显示，避免旧发布行为被默认关闭；配置责任人/部门变化不改变接管人员。历史版本保留原值。
6. 业务审批由业务系统按具体单据与当前权限确定审批人；配置接管人员不授予审批权限。公文起草的用户确认与正式发文审核分别处理。

#### US-13：对话中按需出现表单

作为前台使用者，我希望用自然语言说明目标，遇到多个字段、选择项或需要核对的内容时使用表单，提交后继续当前任务。

1. 普通专家创建为四步，在“输入与输出”配置用户交互，“工作能力”按需展开人工兜底；专家团只组队、沿用固定成员配置，队长与专家团均为三步。无需表单时不添加字段，默认直接对话。
2. 输入字段继续保存于 `interaction.input.fields`：标签、类型、必填/条件、来源与校验各维护一份。“填写方式”提供智能选择、优先对话、集中填表；单选、多选属于具体字段的回答类型。已有“优先选项”配置保留显示与行为，不自动改为其他方式；自动阈值归入用户填写下的“信息不完整时”。
3. `entryFields` 选择任务开始时需要提供的字段；其余在任务缺少信息时收集。已提供或已确认的有效值复用；AI 预填值标记为待确认。表单提交需同时检查值合法性与预填确认，不能仅判断必填项非空。
4. 业务动作前确认使用已有工具参数和确认节点，不另建一份审批表。确认页显示业务对象、关键参数与将产生的动作；修改后生成新确认版本，原确认失效。业务系统既有表单后续通过固定版本的集成契约引用；当前没有可用表单目录，后台不提供伪造的“已接入”选择。
5. 表单提交先校验，失败逐项提示并保留内容；成功才恢复同一任务。提供取消，取消后停止后续动作并保留已完成结果；旧卡片只读，重复提交返回原结果，不重复触发业务动作。
6. 专家团由队长汇总成员的信息缺口，向用户展示同一任务下的交互卡片；成员不各自重复向用户提问。等待业务审批与等待异常接管分别展示，不将“已提交申请”显示为“已审批完成”。

#### US-14：配置用户填写与接收资料

作为实施人员或学校系统管理员，我希望分别配置“要向用户问什么”和“可以接收哪些资料”，能在对应位置找到填写规则或上传限制。

1. 主页面分为“用户填写”和“接收资料”两组。用户填写依次展示填写方式、填写项目、填写提示；填写方式使用紧凑选择框，提供智能选择（默认）、优先对话、集中填表，仅显示当前方式的说明。未定义固定问题时默认直接对话。单选、多选在具体问题中配置；已有“优先选项”值继续显示为“优先选项（已有设置）”，不进行隐式迁移。
2. 信息名称、回答类型、是否必填、收集时机与编辑入口放在同一行。必填信息可选“开始时填写”或“缺少时补充”；条件信息和选填信息显示对应时机。排序、复制、删除收进该行“更多”。编辑字段不触发页面滚回顶部；切换步骤或点击错误提示时才定位，错误所在的折叠区自动展开。
3. 集中填表模式没有填写项时，明确提示先添加填写项；常用问题可快速添加，添加、编辑和复制填写项均使用居中弹窗。允许保存未完成草稿，发布仍校验表单至少一项信息。
4. “预览填写页面”打开静态弹窗，展示开始收集项、后续补充项及资料类型；空表单提示尚未配置，不展示误导性的聊天样例。此入口只展示样式，不调用模型或执行业务。
5. 填写提示直接放在信息列表下，可留空；缺少必要输入时的处理、自动切换表单数量归入该组的“信息不完整时”，默认收起。接收资料展示文字、文档、表格、图片、音频及对应格式；“上传限制”紧跟资料类型，默认收起并显示当前大小、份数摘要。文本文件与文档、表格、图片共用一组限制，录音单独计算。不再设置混合所有选项的“更多设置”。
6. 切换交互方式、资料类型或收起设置均不删除既有字段、入口字段映射、提示、限制或输出配置；保存后重开值保持一致。只读页不允许修改。沿用原输入配置作为唯一数据来源，不新增交互配置副本。
7. 校验错误只展开所属规则：表单阈值或缺失处理错误展开“信息不完整时”，附件上限错误展开上传限制。历史无效值即使当前类型未选中，也展示对应修正项；不展开无关规则。
8. 填写项弹窗默认展示“填写项名称、填写类型、是否必填、填写示例”；选择单选/多选或条件必填时显示对应设置。信息来源、敏感程度、填写限制和内部标识收进高级设置；已有配置保留，隐藏配置校验失败时自动展开。标题和底部操作固定，内容超高时在弹窗内滚动。取消、关闭或按 Esc 不保存本次编辑，保存成功才更新列表。成果字段复用同一居中弹窗。

### 7.3 详细规则的归属

设计覆盖范围不等于创建表单范围。创建允许逐步补充身份、能力和输入输出；通用运行规则有默认值，人工兜底按需展开，保存后继续维护详细配置。原型保持现有 Config、Skill 和工具的字段归属，不新增第二份配置，不推断 Skill 会自动生成输入输出契约。

| 内容 | 保存后的按需配置 | 文档与执行约定 |
|---|---|---|
| 上下文 | 来源、历史策略、轮次、预算 | 当前任务与租户隔离；授权和关键状态优先；外部材料只作数据 |
| 输入输出 | 字段、条件、文件、格式、来源、确认 | 格式有效、人工通过、业务生效分别判断；回执不足不可声明完成 |
| 人工介入 | 工具确认人、交付确认、缺失输入、接管人 | 确认绑定动作和参数；修改后旧确认失效；超时或取消停止后续调用 |
| 执行与失败 | 调用次数、时长、Token、无进展、未知结果策略 | 安全可重试读操作有限重试；未知写结果核验原动作；不能确认则转人工 |
| Skill | 选择固定版本、查看原文、依赖工具 | 标准 Skill 内容由开发/实施维护；不携带使用人权限；按任务选择组合 |

#### 创建时采用的默认值

- 使用校内文本模型；可在工作能力中更换。默认接收文本，输出文字；任务专用字段及附件在用户交互中按需配置。
- 缺少信息先询问；携带用户输入、任务状态和工具结果；保留最近 10 轮对话，上下文预算 16000 Token。
- 受限工具循环、工具调用上限 20、总预算 64000 Token、连续无进展上限 3。模型调用次数、时长和响应超时沿用现有默认配置。
- 新建人工兜底默认关闭，接管人员为空；写操作结果未知先核验，无法确认则停止并保留待核验记录。启用人工兜底后才转交指定人员；已有接管配置保留。
- 开场白留空自动生成，推荐问题为空；语言跟随用户，最多 50 轮，显示过程摘要，使用默认异常提示。
- 以上为本地原型默认值，具体规则由开发实现。保存后改动配置仍将旧测试报告转入历史记录，已发布快照保持不变；旧报告不作为发布前置。

#### 前台交互与人工协作的执行约定

| 对象 / 状态 | 内容及允许操作 | 后续状态 |
|---|---|---|
| 待补充信息 | 对话、选项或表单；复用已知值，AI 推断需确认 | 校验通过→继续任务；失败→保留填写；取消→已取消 |
| 待确认操作 | 显示当前业务对象与关键参数；允许修改、确认、取消 | 确认当前版本→提交业务；修改→新版本待确认 |
| 等待业务审批 | 显示业务单据与业务系统确定的审批角色；申请人只能查看 | 有权审批人处理并返回业务回执→通过/驳回 |
| 结果待核验 | 原动作标识、已知回执与未知项；不自动重发 | 核验确定→同步业务状态；无法确定→停止或等待接管 |
| 等待人工接管 | 显示指定接管人、原因、已完成/未完成事项 | 有效人员领取→人工处理中；转交失败→明确未送达，不宣称已接管 |
| 人工处理中 | 接管人员核对并登记处理结果；业务动作仍检查其业务权限 | 已解决/无法解决；恢复智能体须重新检查条件与确认，禁止重放原写动作 |

**运行端必须校验的绑定：** 每张卡片绑定任务 ID、请求 ID、请求类型、表单/工具定义版本、值版本、允许操作人和当前状态。提交携带请求 ID 与值版本；服务端核验任务归属、最新状态、字段、权限及幂等键后执行。重复请求返回同一回执，过期卡片不覆盖新内容；刷新从任务状态恢复，不依赖聊天消息文本判断是否完成。新增交互只消费后台已发布快照及现行授权，提示词不负责生成任意字段、按钮代码或审批权。

**职责分工：** 系统提示词定义身份与边界；Skill 定义哪些业务步骤需要输入/确认；输入配置及工具契约定义数据；前台使用统一组件呈现；运行端负责校验、等待、恢复、取消与去重。不同业务可采用不同交互组合，无需增加智能体类型。

### 7.4 假设与边界

按对象划分三步或四步、独立输入输出与按需展开人工兜底是本次设计判断，尚未经过高校真实用户可用性测试。独立前台示意使用固定场景与页面内临时状态，切换身份仅为审阅设计，不实现真实鉴权、持久化任务恢复或业务提交；正式运行端须落实上面的绑定与校验约定。预置内置 Skill 与其工具均为模拟目录；工具开发、真实模型评估、并发协作、权限下沉、回执核验和真实取消恢复需要后续工程接入。
