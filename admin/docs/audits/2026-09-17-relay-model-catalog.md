# 自建中转站模型目录与 Agent 选模

日期：2026-09-17。工作目录：`AI Employee OS-web-admin`。

## 当前交付

在“系统设置 → 模型管理”增加中转站配置和模型列表。新建专家的基础资料中直接选择模型，模型参数页使用同一个选择组件和目录。普通 C 端用户不配置模型或凭证。

当前项目仍为浏览器交互原型。中转站真实 Base URL、接口说明及服务端凭证尚未提供；先按 OpenAI 兼容的模型列表格式设计，尚未确认用户中转站的协议。同步按钮明确标记“同步模型（演示）”，只解析本地演示响应，不发送 HTTP，不执行真实模型请求。

## 最小页面与数据合同

| 对象 | 字段 | 规则 |
| --- | --- | --- |
| 中转站 | 标识、名称、Base URL、服务端凭证引用、启停状态 | MVP 管理一个当前中转站；Base URL 包含版本路径，模型列表路径为其下的 `/models`；只保存引用名称，不接收真实 API Key |
| 模型 | 中转站标识、原始模型 ID、展示名称、管理员启用、上游可用状态、输入能力、工具调用能力、同步时间 | 模型 ID 来自响应，只读；新同步模型默认未启用；能力由管理员核对，不从名称猜测图片／音频／工具调用支持 |
| Agent | `modelProviderId` + `model`，模型参数 | 新建时明确选择，无默认代选；只列当前中转站已启用且上游可用的模型 |
| 发布快照 | 模型标识对，以及 `modelDisplayName`、`modelProviderName` | 发布时保存，修改目录展示名不改写该快照；详情显示中转站、模型名称、原始 ID 和参数 |

当前事实源为 `CampusState.modelCenter`，页面、下拉框、发布校验与模型管理操作均读取该目录。旧通用编辑器继续保留自己的历史测试目录，不进入当前单专家 MVP。模型示例名称与 ID 使用 `deepseek-v4`、`glm-5.2`、`deepseek-v3`，保留演示数据标识。已有浏览器的旧演示目录自动更新名称和 ID；旧 Agent 配置通过中转站内的演示 ID 别名继续关联，发布快照与测试摘要不改写，管理员自定义展示名保留。示例能力仍是原型配置，不代表已验证上游模型能力。

模型列表支持名称／ID 搜索、状态筛选、分页、展示名称与能力配置、启停、引用专家数量。管理员配置中转站后手动演示同步、配置模型能力并启用，即可在创建专家时选择。

## 状态与失败行为

- 同步使用 `{ "data": [{ "id": "model-id" }] }` 结构，拒绝非数组、无效／重复 ID 和超大列表。解析成功后原子更新，解析或持久化失败保留原目录。
- 同一中转站重新同步保留展示名、能力配置与管理员启停选择；响应中消失的模型标记下线，保留引用与历史；重新出现时恢复上游可用标记，不自动更改管理员启停状态。
- 模型或中转站停用后，从 Agent 新选择中移除，并阻止相关发布、恢复和回退校验通过；当前已选模型显示不可用，不自动换成另一个模型。真实运行时的拦截仍须服务端实现。
- 更换 Base URL 生成新中转站标识，旧目录标记下线，原 Agent 和版本保持原绑定，管理员须重新选模。不会把原模型 ID 静默指向新地址。
- 图片／音频输入按目录中的能力声明校验；配置了执行能力时要求模型支持工具调用，不再硬编码 `campus-vision`。
- 模型管理操作层仅允许管理员写入；沿用 Campus revision 检查与原子存储，管理记录进入既有审计。已持久化但重读失败时，只允许重新读取，不重复执行原动作。
- Base URL 不接受账号密码、查询参数或片段；凭证引用输入明确禁止真实 Key。当前不具备生产密钥保管能力。

## 真实接口接入边界

目前没有实现服务端模型同步接口、凭证仓库、后台认证或模型调用代理。接入时应由服务端持有中转站地址与真实凭证，读取上游列表，校验完整响应后更新目录，再提供去除敏感配置的管理员目录接口。浏览器不应直接携带中转站 Key 调用上游。

上游不返回能力元数据时，应保留管理员声明；不能因为列表里出现模型就声称它支持图片、音频或工具调用。同步失败与成功返回空列表须区分：失败保留目录，成功空列表表示此次没有可用上游模型。

运行服务读取 Agent 的固定标识对与发布参数，在每次请求时校验账号、专家、服务、模型状态和输入能力。同步模型列表成功也不等于模型推理或工具调用可用；本轮没有增加假连通性检测。
