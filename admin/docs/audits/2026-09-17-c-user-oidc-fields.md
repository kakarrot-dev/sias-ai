## 2. 对方提供什么

| 声明／能力 | 文档契约 | 本平台用途 |
| --- | --- | --- |
| `iss`、`sub` | 验证后的稳定身份标识；不同受控客户端的 `sub` 可能不同 | 后端身份绑定，组合唯一约束，区分大小写，不修改 Issuer 字面值 |
| `name`、`preferred_username` | 请求 `profile` 后可能返回；当前为通用展示值 | 可选展示信息，不能当真实姓名、唯一用户名或自动合并依据 |
| `aud`、`azp`、`exp`、`iat`、`nonce` | Token 校验字段；`azp` 根据 Audience 与实际出现情况校验 | 登录校验，不映射为用户基本资料 |
| `auth_time`、`amr`、`acr` | 认证时间、方式、强度，文档未列出全部实际取值 | 保留在受控认证／会话上下文；不用于推导业务管理员权限 |
| 邮箱／手机号及验证标记 | 明确不释放 | 本期不要求，不因缺失拒绝登录 |
| `user_id`、`principal_id`、`roles`、`kyc_status` | 明确不释放 | 不依赖对方内部用户 ID、角色或实名状态 |
| 头像、账号停用状态 | 未列为保证返回的 Claims | 头像使用默认值；账号状态由本平台明确维护，不伪造上游同步 |
| UserInfo | 可按需调用，必须核对 `sub` 与已验证 ID Token 相同 | 不假定其补齐邮箱、手机号或其他未承诺资料 |

## 3. C 端 MVP 字段建议

### 用户基本资料

| 字段 | 必要性 | 来源与规则 | 后台展示 |
| --- | --- | --- | --- |
| `userId` | 必需 | 本平台后端生成的稳定 ID；不可使用昵称或示例 ID 替代 | 列表和详情，作为聊天、用量、授权的关联键 |
| `displayName` | 可缺省输入 | 可用 OIDC 展示值，缺失时使用本地生成的默认称呼；不要求唯一、不标注为实名 | 列表、详情 |
| `accountStatus` | 必需 | 本地正常／禁用；未来如有注销需求，另行定义注销状态与数据保留规则 | 列表、详情；本地禁用不能被再次登录或自动开户绕过 |
| `createdAt` | 必需 | 本平台首次建号时间 | 列表、详情；不是 Token 的 `iat` 或对方注册时间 |
| `lastLoginAt` | 可空 | 本平台成功建立会话的时间 | 列表、详情；不是最近聊天时间 |
| `avatarUrl` | 非必需 | 当前使用默认头像；对方未承诺返回头像 | 可不配置独立字段 |
| `lastActiveAt` | 非首期必需 | 若后续统计，按真实站内活动更新 | 不从登录时间推算 |

来源展示名称可只读。若以后允许用户维护昵称，应单设本平台昵称与来源，避免每次登录覆盖用户输入；本轮不额外增加资料编辑需求。手机号、邮箱、密码、真实姓名、工号、部门、岗位不加入首期必填字段。

### 外部身份绑定（服务端）

| 字段 | 规则 |
| --- | --- |
| `userId` | 指向本地用户 |
| `oidcIssuer` + `oidcSubject` | 来自已验证 ID Token，`UNIQUE (oidcIssuer, oidcSubject)`；业务记录不直接使用原始 `sub` 关联 |
| `bindingStatus` | 有效／已撤销；保留撤销状态，避免被重新 JIT 建号绕过 |
| `boundAt` | 实际绑定时间 |

登录来源显示为“统一身份登录”，可从绑定配置派生，不需要用户自行填写。`clientId` 属于服务端 RP 配置／接入上下文，不能拿来当用户 ID。Token、Client Secret、授权码、PKCE verifier 不属于用户资料字段。

### 与聊天、用量和后台权限的关系

- 所有会话和用量使用同一个本地 `userId`；用户昵称只作展示或历史快照。服务端从已认证会话确定当前用户，不能信任浏览器请求体传入的归属用户 ID。
- 用量与会话次数来自记录聚合，不把它们当用户可编辑属性，也不把身份 Access Token 当模型调用凭据。
- 登录成功只证明身份，不自动获得全部 Agent 权限、后台管理权限或额度。C 端可使用的 Agent 仍遵循产品开放范围；具体开放策略未在 OIDC 文档中定义。
- 后台操作审计需记录真实的 `operatorUserId`，再附操作人展示名／角色快照；只记录“平台管理员”无法区分多人。

## 5. 文档问题和联调前缺项

1. **域名示例不一致。** 第 3 节指定当前 Issuer 为 `https://api.saygood.top/oidc`，但第 4.5、5.3、7.2 节 HTTP 示例仍写 `Host: fgtoken.cn`。需维护方修正文档并确认环境，以确认后的固定 Issuer 与 Discovery 为准，不照抄混用示例。
2. **Issuer 切换缺少绑定迁移约定。** 文档提及未来切回域名；由于 Issuer 属于身份键，仅修改配置可能令旧用户变成“未绑定”。切换前需明确如何由可信依据迁移到原本地用户，不能双域名宽松校验或按姓名合并。
3. **`digital-employee` 已登记不等于生产已开通。** 需维护方确认本系统环境、专属客户端、HTTPS 后端回调、客户端启用状态及测试账号。凭据按安全渠道交付，不附在本报告或前端配置中。
4. **实际 Claims 样本未验证。** 可在受控联调中核对脱敏后的字段名、类型、缺省情况、认证方式／强度枚举及稳定 `sub`；不要传完整 Token。

建议首期采用“统一登录 → 验证身份 → 查询绑定 → 允许注册时创建最小权限 C 端账号 → 建立本地会话”。允许 JIT、已有真实账号的绑定策略与会话有效期仍需在实施时明确。已禁用、已撤销或冲突绑定不得自动重建账号。

后台列表建议：用户 ID、展示名、登录来源、账号状态、注册时间、最近登录时间、详情。详情展示基础信息、身份绑定状态和该用户的会话／用量入口；不展示密码、Token 或 Secret。本轮只新增此排查报告，未实施认证逻辑或改变原型数据。
