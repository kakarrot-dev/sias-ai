# 专家团创建体验优化

> 历史记录：本文团队独立输入输出及四步创建方案已根据用户纠正撤回。当前以[专家团组队边界修正](2026-09-16-team-assembly-boundary.md)为准；保留本记录用于追溯。
## 发现的问题

- 创建步骤仍用四个大按钮，与普通专家、队长的创建体验不一致；底部“下一步”没有说明去向。
- 尚未选择队长和成员就出现大块黄色告警，缺少队长还重复触发“角色无效”提示。
- 候选列表与已选成员混在一起，勾选立即入团且候选消失，缺少批量确认与取消。
- 团队基本资料沿用“工作方法通过 Skill 维护”的专家说明，责任归属与业务介绍没有层级。
- 检查页只能阅读，缺少名称没有计入检查，成员摘要读取最新草稿名称而非固定版本。

## 实现

- 四步统一为“基本信息 → 队长与成员 → 输入与交付 → 检查团队”，复用现有创建页的步骤条、文字尺寸、内容宽度和固定底部操作。
- 团队名称、简介优先；适用场景按需展开，部门与责任人独立成组。
- 创建时用中性说明引导选人；失效引用等实际问题继续提示。重复角色校验只检查实际选择，不把缺少队长再报成重复错误。
- 队长与普通专家分栏。成员弹窗支持多选、搜索和统一确认，取消不修改草稿；关闭后焦点回到添加按钮。按发布版本展示候选，固定引用版本。
- 检查页提供分组摘要和修改入口，缺项可返回对应步骤；名称为空时保存会返回第一步并聚焦名称，回执缺项定位输出分区及对应输入框。
- 沿用团队自己的输入输出约定、草稿暂存、保存后打开队长并返回团队的流程，不改变发布、授权或执行架构。

## 验证

- 先运行新增回归测试，记录旧页面缺少目标步骤与交互的失败案例；实现后通过。
- `admin:test`：20 个文件、303 项测试通过，覆盖多选取消/确认、搜索保留勾选、暂存恢复、缺少名称定位、检查项定位输出，以及已有跨页保存与返回流程。
- `admin:build`（包含 `admin:check`）通过；保留既有的大包体积提示。`git diff --check` 通过。
- 浏览器在 1280×800 检查四步页面与选择弹窗，无横向溢出。实际验证取消不改成员，搜索后保留勾选，两位成员一次加入。
- 实际创建临时团队，配置“先填表单”、办事主题字段及 OA 回执来源和完成证据；保存、刷新后重新打开，成员、表单和完成条件均保留。
- 临时验收团队已通过页面移除，未发布；最终恢复空白创建页面。最终浏览器验收没有新增 warning/error，开发过程中的一次 Vite 热更新瞬态错误已恢复。
