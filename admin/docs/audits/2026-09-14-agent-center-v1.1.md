## 交付结果

公开 `#/agents` 已恢复，七个一级导航沿用原框架。专家可用名称和提示词创建，独立配置输入、输出、Skill、MCP 的具体工具及内置工具。交付确认统一从输出配置读取，工具执行前确认按每个动作独立保存。

专家团通过选择既有专家、指定队长和固定版本组队。队长提示词负责目标、分工和步骤；团队展示队长的固定版本提示词与输入输出，只保存团队关系和资料。未组完也能保存。新建和编辑团队均可在处理未保存内容后打开专家，并返回原团队。旧团队 dispatch 只读保留在历史快照，不会自动写入队长。

新增配置完整性检查、可选五样例测试、模拟申请／驳回／发布失败重试、授权同步、停用、回退与历史报告。发布不要求百例三轮。历史快照与既有运行引用不变；当前使用授权独立于历史版本。

所有人物、组织、候选、工具调用、测试、审批、发布与交付均为前端样例。没有新增后端代码、真实模型调用或 MCP 连接。

## 浏览器实测

使用 Codex 内置浏览器，从公开入口实际点击。初始测试地址为 `http://127.0.0.1:5183/`；后续在独立端口 `5184` 中验证版本及异常样例，避免影响用户正在操作的浏览器数据。

1. 创建“材料核对专家 · 验收示例”，仅填名称与工作说明；刷新读回同一草稿，输入输出默认文字，能力为空。
2. 新增“办理事项”输入字段，切换到输出时保留未保存草稿；设置 Markdown 与成果要求后一起保存。选取 MCP 服务中的一个读取工具并保存刷新。
3. 当前配置预览缺少办理事项时出现 text 追问与必填提示；补齐后提交。逐人审核批准林晓后，周宁仍为待确认。
4. 将确认内容从 v1 修改为 v2，提交旧版本被阻止；确认 v2 后重复提交显示状态未再次推进。没有执行外部操作。
5. 已发布团队引用队长 v1，而目录队长已为 v2；基于团队版本创建草稿、更新队长引用并保存，团队发布版本仍是 v1。模拟发布失败后版本仍为 v1；重试生成 v2，运行记录仍固定团队 v1。
6. 仅填名称创建“尚未组好的专家团 · 验收”，刷新后保留，提示缺队长与成员；后来选择三位专家并指定队长。打开队长时出现保存／放弃／停留，保存后打开专家并显示返回团队入口。
7. 1440×900 检查列表和长名称、3000 字提示词；1280×720 检查组团页及输入字段抽屉。主要操作可见，抽屉在视口内滚动。DOM 测量文档宽度分别为 1440 和 1280，没有整页横向溢出。
8. 独立验收页读取的浏览器 error／warn 日志为空。

## 输入与输出页面体验调整

- 输入页使用“资料类型 → 要询问的信息 → 缺失信息如何补充 → 资料限制”的提问顺序。资料类型带用途和格式示例，常用信息可直接添加；无需固定提问时可以留空。信息名称、回答方式、是否必须提供和例子为默认编辑内容，其余规则放在独立页签，内部标识仍自动生成。
- 输出页使用带例子的交付样式卡，将要求、小标题、表格列和核对对象用普通语言呈现。空白要求可填入具体示例；已有内容不被覆盖，切换样式保留原章节、字段、接收人与核对配置。
- 两页均使用当前编辑值派生效果示意，显示开始填写／后续询问信息、文件样式、实际表格列、小标题或逐人交付。没有在示意中调用模型、生成文件或发送内容。保留原保存草稿和独立交互预览。
- 删除仅关联开始填写的信息时，确认同时移除其开场提问；被条件或成果核对引用的信息继续阻止删除，并用中文定位关联设置。
- 修正自动补问的表单数量设置：未达到自定义数量时可继续通过对话补充；达到数量或需要日期、人员等控件时显示表单。
- 新增 7 项回归，覆盖示例添加、开始填写与后续询问、资料类型切换后限制值保留、默认编辑保留其他规则、样式与列名预览、引用保护、自动补问数量和 App 保存刷新。全量 13 文件 / 181 项通过，类型检查、构建通过；主入口仍有原有体积提示。
- 独立端口 5184 浏览器实测：添加办事主题与自定义用途说明、简化抽屉、表格交付和具体内容要求、两列效果示意、保存刷新。1280×720 下页面宽度为 1280，设置中无折叠面板，浏览器 error／warn 为空。原 5183 用户页面未被导航或重置。
