## 范围与验收合同

继续使用现有 React / TypeScript / Vite、CampusState / Config、PrototypeStore、公共能力目录、人员目录和 Hash 路由。本轮交付桌面 Web 交互原型的本地持久化 CRUD；不新增后端、数据库、模型调用或真实执行服务。

验收：每次只显示一个配置区块；返回和刷新保留内容；草稿允许未完成但拦截无效已填字段；发布检查完整配置与当前版本报告；保存失败不丢表单；列表可查、详情可读、草稿可改、无引用草稿可删；旧发布快照不得变化。

## 页面步骤

专家创建与编辑共 11 步：基础信息 → 职责与提示词 → 模型与上下文 → 输入契约 → 输出与验收 → 知识与记忆 → 工具 → 技能 → 运行与安全 → 对话体验 → 检查配置。

每次只显示当前区块，侧边导航支持返回修改和跨步补充；下一步校验当前区块。任意步骤可保存未完成草稿，最终回顾列出缺项并可定位。发布在保存后的“测试与发布”页面进行。

专家团创建为基础信息 → 选择成员与队长 → 检查团队三步。复用原有固定成员与队长版本、授权、引用、发布规则，不扩展动态编排。

## 字段映射与单一归属

| 文档责任 | 实现字段与界面 | 规则 |
| --- | --- | --- |
| A0 定义身份、名称、负责人、生命周期与版本 | Agent.id / key / versions / live / disabled；Config.name / description / owner / department | 系统身份固定；定义与 Run 状态分开；查看入口只读 |
| A1 支持范围、非目标、前置条件、缺失输入、完成标准及证据 | Config.definition.task | 支持保存未完成草稿，完整配置检查要求职责、完成标准与证据 |
| A1 Prompt 与变量 | Config.prompt / promptReferences；已有模板与变量按钮 | 提示词与定义版本一起固定；不另建第二份 Prompt |
| A2 模型档案与输出长度 | Config.model / temperature / maxTokens；agent-definition.ts 的 modelProfiles | 原型模型能力声明；不支持的参数不展示；上下文加输出不得超容量 |
| A3 输入输出协议 | Config.interaction.input / output | 复用字段类型、必填、枚举、范围、条件、来源与校验；新版不再清空输出结构 |
| A4 上下文 | Config.definition.context | 来源白名单、每轮状态、历史窗口/摘要、Token 预算；无关凭据与外部指令不能成为系统授权 |
| A5 知识 | Config.expert.knowledgeIds + definition.knowledge | 绑定已有示例资产；检索档案、业务范围和证据不足行为；固定来源与冲突策略 |
| A6 记忆 | 明示未启用 | 缺少存储及更正、删除等能力，不提供假启用开关 |
| A7 / A8 Skill、工具与 MCP | 原有 Config.tools / nodes，引用 capabilities.json | 固定能力版本；Skill 逐动作控制；MCP 选择登记的能力，不复制 Server 凭据 |
| A9 执行与预算 | 原有 Config.limits.steps / minutes / modelSeconds；definition.runtime | 分开限制模型调用、工具调用、总 Token、活动时长和无进展次数；不把对话轮次当模型调用数 |
| A10 / A11 权限、人工、安全与恢复 | 原有 grants / tools / nodes / safety；definition.governance / runtime.unknownResult | 受控执行档案 v1；未知结果不得盲目重试；人工接管责任人引用人员目录 |
| O2 测试与观测 | 原有 Config.testSet / Agent.tests / testHistory；definition.governance.traceRef | 新版发布要求与当前配置摘要一致的通过报告；样例仍明确标为模拟 |
| 对话体验（既有扩展） | 原有 Config.opening / expert.questions / replyLanguage / maxRounds / fallback | 保留已有头像、提示词模板、技能正文与独立调试 |

新增 definition 只存原结构中缺失的字段。模型、人员、工具、知识、输入输出均继续使用原字段；没有将 Run ID、剩余额度、审批结果、实时运行状态设计成配置项。

公共档案是受控的前端示例引用。未接入的独立 Prompt / Schema 资产库、真实评测、部署入口、凭据、费用预留、沙箱、长期记忆、断点恢复、多运行引擎和 P2 动态委派不在本轮冒充可用。输入输出字段在此版本内固定，尚非独立共享 Schema 资源。

## CRUD 与数据保护

- 列表：类型、状态、部门过滤，名称/简介/责任人/ID 搜索，更新时间/名称排序、分页；展示模型、能力数量、版本与负责人，提供查看、编辑、管理及删除。
- 查看：`#/agents/:id/view` 只展示已保存配置，不采用未保存编辑缓存；历史版本显示相应定义与输入输出。
- 创建/编辑：写入当前浏览器 localStorage 的既有 campus 分区；未保存的字段和当前步骤在 sessionStorage 中按身份与对象隔离，刷新续填。
- 数字无效时保留表单并阻止保存，不让 JSON 把 NaN 转成 null 覆盖最后一份有效暂存。
- 保存由既有事务写入；失败回滚，成功但读回失败时只重试读取，不重复创建。
- 删除先确认；有发布历史、运行、测试或团队引用的对象不能删除，保留既有停用与追溯流程。
- 旧数据只在编辑副本中投影。新版定义明确保留输入输出、追问方式和交付确认，历史快照与旧测试摘要不自动改写。
