可以从**读者需要做什么**出发，把文档组织成一条清楚的阅读路径。

### 建议的文档结构

| 章节 | 要回答的问题 | 建议呈现 |
| :--- | :--- | :--- |
| 目标用户 | 谁会使用这个产品？ | 典型角色与使用情境 |
| 核心问题 | 当前流程哪里最费时间？ | 一个具体的使用前后对比 |
| 使用流程 | 怎样完成第一件事？ | 分步说明与界面截图 |
| 能力边界 | 哪些可以做，哪些需要确认？ | 支持范围与限制说明 |

### 先准备这些材料

- **产品定位**：用一句话说明它服务谁、解决什么问题。
- **使用场景**：选一个最常发生的具体情境。
  - 输入：用户提供什么资料。
  - 输出：用户最终得到什么结果。
- **界面素材**：一张主界面图和一份输出示例。

### 推荐的整理顺序

1. 明确目标读者和文档用途。
2. 写出主流程，再补充必要的例外情况。
3. 用真实案例检查每一段说明是否清楚。

> 把“产品支持什么”写成“读者可以完成什么”，会更容易理解。
>
> 本条为静态排版示例，未调用模型或执行真实操作。

### 结构化内容示例

可以先把最小结构整理成 `JSON`，再扩展为正式文档：

```json
{
  "title": "Agent 产品介绍",
  "audience": "初次使用的师生",
  "sections": [
    "目标用户",
    "核心问题",
    "使用流程",
    "能力边界"
  ]
}
```
